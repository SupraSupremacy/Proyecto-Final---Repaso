Módulo 1

// Módulo 1 — Mantenimiento y aseguramiento de la operación del sistema informático

Duración

8 semanas

Objetivos del módulo

Desarrollar las competencias que permitan definir planes operativos y contingenciales, utilizando normas ISO, estándares internacionales y buenas prácticas como las que implementa ITIL v3 y normas ISO, para mantener la operación y la sostenibilidad de un sistema computacional.

Herramientas utilizadas

  • Visual Studio
  • C#
  • .NET Framework 4.8
  • Windows Forms
  • ADO.NET (System.Data)
  • MSBuild

Definiciones y funciones de las herramientas

Visual Studio

IDE para desarrollar, depurar, compilar y desplegar aplicaciones; incluye diseñador visual, IntelliSense y gestión de proyectos.

Lo que aprendimos: Crear soluciones, diseñar formularios, compilar, depurar con breakpoints y administrar referencias.

Ver a fondo

Visual Studio organiza el proyecto en solución, proyecto, formularios y código. Se aprende a validar entradas, separar lógica por eventos y depurar paso a paso para encontrar estados incorrectos. En la práctica, esto ayudó a construir interfaces WinForms con DataGridView y botones, evitando duplicar lógica y detectando valores nulos antes de guardar. También se usó para configurar compilación en Debug/Release y revisar referencias externas.

C#

Lenguaje de programación orientado a objetos del ecosistema .NET.

Lo que aprendimos: Sintaxis, clases, eventos, validaciones, manejo de excepciones y programación orientada a objetos.

Ver a fondo

C# permitió modelar clases y métodos para el aplicativo, encapsular datos y responder a eventos de la interfaz. Se practicó validación, conversión de tipos, recorridos de colecciones y manejo de excepciones. La curva incluyó pasar de scripts simples a un proyecto con múltiples archivos, manteniendo responsabilidades separadas y usando métodos reutilizables para cálculos.

.NET Framework 4.8

Runtime y librerías base de Microsoft para ejecutar aplicaciones Windows y servicios sobre CLR.

Lo que aprendimos: Trabajar con ensamblados, namespaces, configuración de proyecto y compilaciones Debug/Release.

Ver a fondo

Se comprendió el rol del CLR, los ensamblados y la configuración App.config al compilar un proyecto WinForms. El trabajo con assemblies y referencias ayudó a resolver errores de compilación y a entender dependencias. También se vio cómo el mismo código puede ejecutarse en modo Debug para inspección y Release para entrega final.

Windows Forms

Framework de interfaz gráfica para aplicaciones de escritorio Windows, basado en controles y eventos.

Lo que aprendimos: Usar controles, eventos, estados de interfaz y grillas/listas para capturar y mostrar datos.

Ver a fondo

WinForms se usó para diseñar formularios con botones, ComboBox, ListView y DataGridView. Se aprendió a actualizar la interfaz desde eventos, mantener sincronizados datos de memoria y controles visuales, y a calcular totales en tiempo real. La práctica incluyó validar campos obligatorios y limpiar controles después de cada operación.

ADO.NET (System.Data)

Conjunto de clases para acceder a datos: conexiones, comandos, adaptadores y conjuntos de datos.

Lo que aprendimos: Conectar, consultar, insertar, actualizar y mostrar datos con DataSet/DataAdapter.

Ver a fondo

Se usaron conexiones, comandos y DataAdapter para mover datos entre SQL/Access y la interfaz. La curva pasó de consultar tablas a mostrar resultados en DataGridView/ComboBox y de insertar o actualizar registros con validación. También se entendió la importancia de cerrar conexiones y manejar errores de proveedor de datos.

MSBuild

Motor de compilación que procesa archivos de proyecto para compilar, empaquetar y publicar soluciones.

Lo que aprendimos: Compilar desde IDE/CLI, configurar targets y resolver dependencias del proyecto.

Ver a fondo

MSBuild se usó indirectamente desde el IDE para compilar el .csproj. Se aprendió que un proyecto define propiedades, referencias e inclusiones de archivos, y que los cambios de estructura afectan la compilación. La práctica incluyó verificar errores en Console/output y entender salidas bin/Debug.

Situación problemática

Las caídas constantes en los sistemas informáticos no se tienen mitigadas debido a que no se cuenta con un área que se encargue del mantenimiento y aseguramiento de la operación. Esto genera atrasos en la cadena productiva, erogación de recursos de manera innecesaria y una mala imagen de la entidad.
